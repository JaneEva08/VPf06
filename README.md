# Telegram-бот с короткой и долгой памятью (VPf06)

Бот с **комбинированной памятью**: ведёт связный диалог (короткая память) и отвечает по загруженным документам (долгая память, RAG).

## Пример результата

После загрузки `company.txt` бот отвечает по документу и помнит диалог:

> **Вы:** Где у вас есть офисы?
> **Бот:** Офисы есть в Москве и Санкт-Петербурге.
> **Вы:** Вы делаете Telegram-боты? — **Бот:** Да, делаем Telegram-боты с ИИ под ключ. Разработка занимает от 10 дней.
> **Вы:** А сроки? — **Бот:** Telegram-боты с ИИ делаем от 10 дней. Для лендингов срок — от 7 дней, для интернет-магазинов — от 3 недель.

Скриншоты: [`docs/screenshots/`](docs/screenshots/). Отчёт о прогоне: [`HOMEWORK.md`](HOMEWORK.md).

## Как устроена память

| Тип | Что хранит | Где | Как |
|---|---|---|---|
| Короткая | последние 10 сообщений диалога (вопросы и ответы) | оперативка, `dict user_id -> deque(maxlen=10)` | старые сообщения вытесняются автоматически |
| Долгая | текст PDF / DOCX / TXT | ChromaDB на диске (`./memory`) | текст → чанки → эмбеддинги → векторная БД |

### Долгая память (загрузка документа)
1. Пользователь присылает файл, бот скачивает его в `./uploads/<user_id>/`.
2. Текст извлекается (`pypdf` для PDF, `python-docx` для DOCX, чтение для TXT).
3. Текст режется на пересекающиеся чанки (~500 символов, перекрытие 50).
4. Эмбеддинги превращают чанки в векторы: через API провайдера (`EMBED_PROVIDER=api`, `text-embedding-3-small`) или локальной моделью (`EMBED_PROVIDER=local`, `paraphrase-multilingual-MiniLM-L12-v2`, библиотека `fastembed`).
5. Векторы + метаданные (`user_id`, `doc_id`, `file_name`, `chunk_index`) сохраняются в Chroma (cosine).

### Логика запроса
1. Вопрос пользователя → эмбеддинг → поиск 5 ближайших чанков в Chroma (фильтр по `user_id`, чужие документы не видны). Короткое уточнение («А сроки?») ищется вместе с предыдущим вопросом. Чанки дальше порога `RAG_MAX_DISTANCE` отбрасываются.
2. В модель уходит: системный промпт + короткая история (до 10 сообщений) + вопрос с найденными фрагментами (в тегах `<documents>`, как данные, а не инструкции).
3. Ответ отправляется пользователю; в историю сохраняется чистый вопрос и ответ (без фрагментов, чтобы контекст не раздувался).

Если в документах ответа нет, модель опирается на историю диалога и общие знания и не выдумывает факты о документе.

## Библиотеки
`aiogram 3` (Telegram), `openai` (чат, при `EMBED_PROVIDER=api` и эмбеддинги), `fastembed` (локальные эмбеддинги), `chromadb` (векторная БД), `pypdf`, `python-docx`, `python-dotenv`.

## Запуск
```bash
python -m pip install -r requirements.txt
cp .env.example .env   # вписать BOT_TOKEN (от @BotFather), OPENAI_API_KEY и при необходимости OPENAI_BASE_URL
python probe_provider.py   # проверка: отвечает ли чат и отдаёт ли провайдер эмбеддинги
python bot.py
```

Тесты: `python -m pip install -r requirements-dev.txt && python -m pytest -q`.

## Структура
- `bot.py` — Telegram-хендлеры, OpenAI, Chroma
- `core.py` — логика без внешних сервисов: чанки, короткая память, сборка запроса, порог
- `probe_provider.py` — проверка провайдера
- `tests/` — тесты на заглушках
- `company.txt` — пример документа

## Команды
- `/start` — приветствие
- `/reset` — очистить короткую память
- `/forget` — удалить свои документы из долгой памяти

## Как проверить
1. Отправьте `company.txt` (есть в репозитории) — бот ответит, сколько чанков сохранено.
2. «Где у вас есть офисы?» → «в Москве и Санкт-Петербурге» (из документа).
3. «Какой был прошлый вопрос?» → бот вспомнит предыдущий вопрос (короткая память).

## Заметки
- Модель задаётся `CHAT_MODEL`. Reasoning-модели не принимают `temperature`, поэтому она не передаётся; лимит ответа (`MAX_COMPLETION_TOKENS`) необязателен — он включает «мысли» модели.
- Если модель вернула пустой ответ, в историю он не сохраняется.
- Загруженный файл после индексации удаляется, в базе остаются только чанки; `/forget` стирает их.
- Короткая память хранится в оперативке и сбрасывается при перезапуске; долгая сохраняется на диске.
