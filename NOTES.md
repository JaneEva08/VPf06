## Разбор урока

1. **О чём урок.**
   - Контекстное окно и его ограничения (цена, скорость, лимит длины).
   - Короткая память = история диалога; приёмы: последние N, резюме, циклическое обновление.
   - Долгая память = факты и документы: чанки → эмбеддинги → векторная БД (Chroma).
   - Практика: два бота на aiogram 3 + OpenAI, затем объединение в одного.
2. **Требования ДЗ** — см. чек-лист ниже. Уровней нет. Формат сдачи: репозиторий, zip или скриншоты. Куратор, судя по тексту, смотрит, что описана память, пояснены хранение, библиотеки и логика запроса, и что код рабочий.

4. **Замены.**

5. **Ошибки урока** — в разделе «Материал для отчёта».

## Материал для отчёта

**Замены инструментов.**
- Cursor → Claude Code → так я работаю.
- `gpt-3.5-turbo` / `gpt-5-mini` → `gpt-6-luna` через aiprimetech → дешевле, мой провайдер.
- `OpenAI` + `asyncio.to_thread` → `AsyncOpenAI` → без лишних потоков.
- Загрузка файла через `aiohttp` и URL с токеном бота → `bot.download()` → токен не попадает в адрес запроса и логи.

**Ошибки и неточности урока (страницы PDF).**
- **стр. 11 и 34.** История дублирует текущий вопрос: сообщение пользователя сначала кладётся в память, а затем `build_messages…` добавляет его ещё раз. В моём коде вопрос попадает в историю только после ответа, вместе с ответом.
- **стр. 32.** GPT-4o-mini назван моделью «пятого поколения», не принимающей `temperature` и `max_tokens`. Это неверно: ограничение у reasoning-моделей (серия gpt-5 и др.), 4o-mini параметры принимает. Лимит у них называется `max_completion_tokens` и включает «мысли», поэтому его легко исчерпать до ответа.
- **стр. 23 и 34.** Хендлер `F.text & ~F.via_bot` ловит и команды (`/reset`, `/forget` ушли бы в модель). У меня `~F.text.startswith("/")`.
- **стр. 22–23, 33–34.** `os.environ["OPENAI_API_KEY"] = …` и `OpenAI()` создаются на каждое сообщение. У меня один клиент при старте.
- **стр. 22, 24.** Файл сохраняется под исходным именем: возможен выход из папки (`../`) и перезапись одноимённых файлов; нет проверки расширения и размера до скачивания. У меня: очистка имени, префикс `doc_id`, проверки, удаление файла после индексации.
- **стр. 10, 21.** Синхронный `client.chat.completions.create` в `asyncio.to_thread`; по умолчанию `gpt-3.5-turbo`, `temperature=0.7`, `max_tokens=500` — устарело и не работает с моделями нового поколения.
- **стр. 26.** В тесте указано сообщение «Чанки созданы. Задавайте вопрос!», а в коде урока другое: «Документ сохранён и проиндексирован».
- **стр. 36–37.** В задании «выбери один из двух вариантов», а перечислено три.
- **стр. 33.** Урок сам показывает, что бот с долгой памятью теряет контекст беседы; это и есть причина объединять память.
- Урок не упоминает: порог релевантности (бот всегда подставляет топ-5 даже для чужих вопросов), вопрос-уточнение без контекста («А сроки?»), удаление данных пользователя, инъекцию через текст документа.

**Решения, принятые мной.**
- Эмбеддинги: у aiprimetech (группа Codex) их нет, поэтому по умолчанию локальная модель `paraphrase-multilingual-MiniLM-L12-v2` (`EMBED_PROVIDER=local`); отдельный провайдер — запасной вариант (`EMBED_BASE_URL`). Плюс для заказов: данные не уходят третьим лицам. Минус: порог `RAG_MAX_DISTANCE` у локальной модели другой, подбирается заново; модель слабее облачной.
- Имя коллекции Chroma зависит от модели эмбеддингов, чтобы векторы разной размерности не смешивались.
- Пустой ответ модели не сохраняется в историю, пользователь получает отдельное сообщение.
- Порог релевантности 0.75 (косинусное расстояние) — стартовое значение, подбирается на локальном прогоне.
- Короткое уточнение (до 40 символов) ищется вместе с предыдущим вопросом.
- Текст документа обёрнут в `<documents>` и помечен в системном промпте как данные, не инструкции. Это снижает риск инъекции через файл, но не исключает его.
- Файл после индексации удаляется: в базе остаются только чанки; `/forget` стирает и их.
- `temperature` не передаётся, `max_completion_tokens` задаётся только по желанию.
- Логика вынесена в `core.py`, чтобы тестировать её без ключей.

**Не сделано.**
- Резюмирование истории (приём из урока №2): при 10 сообщениях старые просто вытесняются.
- Хранение короткой памяти на диске: после перезапуска история пропадает (по заданию достаточно оперативки).
- Реальный прогон и скриншоты — локально.
- Разбор PDF с таблицами и сканов (OCR) — вне задания.
